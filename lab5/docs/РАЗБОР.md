# Лабораторная работа №5 — полный разбор и защита

**Вариант 13 — «Учёт продуктов в магазине. Категории изделий».**
Тема: микросервисное приложение с PostgreSQL и Docker Compose.

---

## 1. Что требовалось

1. Реализовать несколько микросервисов.
2. Настроить взаимодействие между ними.
3. Настроить одновременный запуск и работу.

Требования:

* первый микросервис хранит данные в БД, БД запускается в контейнере;
* второй микросервис реализует функции основной формы лаб №2 и №3:
  * вывод списка;
  * добавление;
  * изменение;
  * удаление;
  * выдачу файлов отчётов;
* во втором сервисе **два контроллера**: CRUD и отчёты;
* отчёты формируются сразу, без плагинной логики;
* второй сервис общается с первым через общую БД или HTTP;
* одновременный запуск — Docker Compose.

Для варианта 13:

* Excel — продукты в наличии (название + описание);
* PDF — круглая диаграмма: сколько продуктов какой категории нет в наличии;
* Word — все продукты, шапка из первой строки и первого столбца,
  идентификаторы в первом столбце, при пустом количестве — «отсутствует».

## 4. База данных

Контейнер `postgres:16`, БД `productcatalog`.

```sql
CREATE TABLE Categories (
    Id   SERIAL PRIMARY KEY,
    Name TEXT NOT NULL UNIQUE
);

CREATE TABLE Products (
    Id          SERIAL PRIMARY KEY,
    Name        TEXT NOT NULL,
    Description TEXT NOT NULL DEFAULT '',
    Category    TEXT NOT NULL,
    Quantity    INTEGER NULL
);
```

* `Categories` — данные первого сервиса;
* `Products` — данные второго;
* категория в продукте хранится текстом, без внешнего ключа;
* при старте создаются 4 стартовые категории;
* данные сохраняются в Docker volume `postgres-data`.

## 6. Второй сервис — продукты

### 6.1. `ProductsController`

Маршрут `/api/products`:

| Метод | Маршрут | Действие |
|---|---|---|
| `GET` | `/api/products` | все продукты |
| `GET` | `/api/products/{id}` | по Id |
| `POST` | `/api/products` | создать |
| `PUT` | `/api/products/{id}` | изменить |
| `DELETE` | `/api/products/{id}` | удалить |

Тело:

```json
{
  "name": "Молоко 3,2%",
  "description": "Пастеризованное молоко 1 л",
  "category": "Молочные продукты",
  "quantity": 10
}
```

Валидация:

* название обязательно;
* категория обязательна;
* категория должна существовать в `Categories` (данные первого сервиса);
* количество `null` или `>= 0`.

### 6.2. `ReportsController`

Маршрут `/api/reports`:

| Метод | Маршрут | Файл |
|---|---|---|
| `GET` | `/api/reports/products-in-stock` | `products-in-stock.xlsx` |
| `GET` | `/api/reports/out-of-stock-pie` | `out-of-stock-pie.pdf` |
| `GET` | `/api/reports/all-products` | `all-products.docx` |

Файлы формируются сразу в контроллере/генераторе, без плагинной инфраструктуры.

## 7. Как формируются отчёты

### Excel

* ClosedXML;
* продукты с `Quantity > 0`;
* один столбец «Продукт»;
* каждая строка: название и описание.

### PDF

* QuestPDF + SVG;
* продукты с `Quantity is null or <= 0`, сгруппированные по категориям;
* круглая диаграмма + таблица категорий/количеств.

> Диаграмма строится как SVG, а не через `System.Drawing`, чтобы работать в
> Linux-контейнере.

### Word

* Open XML SDK;
* все продукты;
* таблица:
  * первая строка: пустая ячейка, «Название», «Категория», «Количество»;
  * первый столбец: идентификаторы;
  * пустое количество — «отсутствует».

## 8. Docker Compose

| Сервис | Контейнер | Порты |
|---|---|---|
| PostgreSQL | `lab5-postgres` | `5433:5432` |
| Категории | `lab5-categories-api` | `8080:8080` |
| Продукты | `lab5-products-api` | `8081:8080` |

* `postgres` имеет healthcheck;
* categories-api ждёт healthcheck;
* products-api ждёт PostgreSQL и запуск categories-api;
* внутри сети Compose сервисы обращаются к БД по `postgres:5432`;
* на хост PostgreSQL проброшен на `5433`, чтобы не конфликтовать с локальным
  PostgreSQL;
* данные PostgreSQL сохраняются в volume `postgres-data`.

## 9. Запуск

```powershell
docker compose -f lab5/docker-compose.yml up --build -d
docker compose -f lab5/docker-compose.yml ps
```

Адреса:

* Swagger категорий: `http://localhost:8080/swagger`;
* Swagger продуктов: `http://localhost:8081/swagger`;
* API категорий: `http://localhost:8080/api/categories`;
* API продуктов: `http://localhost:8081/api/products`;
* отчёты: `http://localhost:8081/api/reports/...`.

Остановка:

```powershell
docker compose -f lab5/docker-compose.yml down -v
```

## 11. Вероятные вопросы и ответы

**Как сервисы общаются?**
Через общую БД PostgreSQL. Второй сервис читает `Categories` и проверяет
категорию перед созданием/изменением продукта. Это разрешено заданием.

**Почему PostgreSQL, а не SQLite?**
В лабе №5 требуется БД в отдельном контейнере и общая БД для двух сервисов.
PostgreSQL — стандартный вариант для такой связки.

**Почему первый сервис изменён?**
В лабе №4 он был на SQLite. Для lab5 он переведён на Npgsql/PostgreSQL, CRUD и
API остались теми же. Ветка `lab4` сохранена в исходном виде.

**Зачем два контроллера?**
По заданию: один — CRUD с валидацией, второй — выдача файлов отчётов.

**Где логика плагинов?**
Её нет: в lab5 разрешено/требуется формировать файлы сразу. Плагины остались в
лабе №3, здесь они не используются.

**Как формируется PDF без Windows-графики?**
Круговая диаграмма строится как SVG и вставляется в QuestPDF; это работает в
Linux-контейнере.

**Как проверяется категория?**
Перед `POST`/`PUT` продукта выполняется запрос к `Categories`. Если категории
нет — `400 Bad Request`.

**Что будет, если PostgreSQL ещё не готов?**
Compose healthcheck задерживает запуск сервисов; кроме того, оба сервиса
делают несколько попыток подключения.

**Почему порт PostgreSQL 5433?**
Чтобы не конфликтовать с локальным PostgreSQL на 5432. Внутри Docker-сети
используется стандартный `postgres:5432`.

**Как сохраняются данные?**
В volume `postgres-data`; после `down -v` volume удаляется.

## 12. Ограничения и нюансы

* в учебном стенде пароль PostgreSQL находится в compose/appsettings;
* второй сервис при старте также гарантирует наличие таблицы `Categories` и
  стартовых категорий — для устойчивости общего запуска; владельцем CRUD
  категорий остаётся первый сервис;
* отчёты формируются прямым кодом, без плагинов — это требование lab5;
* PDF-диаграмма — SVG внутри PDF, а не растровое изображение;
* PDF-файлы заданий в репозиторий не включены.

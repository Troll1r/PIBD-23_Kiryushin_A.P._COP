## 1. Что требовалось

По варианту 13 нужен компонент из блока **«Визуальный компонент выбора»**:

> Выпадающий список. Список заполняется через метод, передающий строку.

На оценку «3» достаточно только этого компонента. Блоки ввода и вывода
списков в лабе №1 не требуются.

Обязательные возможности компонента:

* метод добавления непустой строки, если такой строки ещё нет;
* отдельный публичный метод очистки списка;
* свойство `SelectedValue` с `get` и `set`;
* событие изменения выбранного значения.

---

## 2. Архитектура решения

```text
Lab1.TestApp (WinForms)
        │ использует публичный API
        ▼
SelectionControlLibrary
        │
        └── ComboBoxSelector : UserControl
                │
                └── private ComboBox (внутренняя деталь)
```

Главная идея: тестовое приложение **не работает с внутренним `ComboBox`**.
Оно видит только `ComboBoxSelector` и его публичные члены. Внутренний
`ComboBox` — деталь реализации.

## 4. Публичный API `ComboBoxSelector`

| Член | Тип | Назначение |
|---|---|---|
| `AddValue(string value)` | метод | Добавляет строку, если её ещё нет. Пустую строку/пробелы отклоняет через `ArgumentException` |
| `ClearValues()` | метод | Полностью очищает список |
| `SelectedValue` | `string`, get/set | Выбранное значение. `get` возвращает `""`, если ничего не выбрано |
| `ItemCount` | `int`, get | Количество строк в списке |
| `SelectedValueChanged` | событие | Возникает при изменении выбранного значения |

Аргументы события `SelectedValueChangedEventArgs`:

* `OldValue` — прежнее значение;
* `NewValue` — новое значение.

---

## 5. Как проходит сигнал

1. Пользователь нажимает «Добавить».
2. `MainForm` вызывает `comboBoxSelector1.AddValue(...)`.
3. Компонент проверяет строку и добавляет её во внутренний `ComboBox.Items`.
4. Пользователь выбирает элемент в выпадающем списке.
5. Внутренний `ComboBox` вызывает `SelectedIndexChanged`.
6. Приватный обработчик `ComboBox_SelectedIndexChanged` сравнивает новое значение с предыдущим.
7. Компонент вызывает `SelectedValueChanged?.Invoke(...)`.
8. `MainForm` пишет старые/новые значения в журнал и обновляет статус.

Ключевой момент: **компонент не знает о `MainForm`**. Он только публикует событие.
Форма знает о компоненте и подписывается на событие.

---

## 6. Почему это компонентный подход

* Компонент собран в отдельной библиотеке;
* у него есть публичный контракт (методы, свойство, событие);
* внутренняя реализация скрыта;
* компонент можно подключить к другому WinForms-проекту;
* связь с клиентом идёт через событие, а не через прямой вызов формы.

Термины для защиты:

* **инкапсуляция** — `ComboBox` приватный;
* **слабая связанность** — событие вместо прямого вызова;
* **переиспользуемость** — отдельная библиотека и NuGet-пакет;
* **публичный контракт** — `AddValue`, `ClearValues`, `SelectedValue`, событие.

## 9. Вероятные вопросы и ответы

**Почему нет отдельного интерфейса?**
В лабе один компонент и одна реализация. Контракт задан его публичным API.
Если появится вторая реализация, можно выделить `IStringSelector` и перевести
форму на интерфейс без изменения логики.

**Почему `ComboBox` приватный?**
Чтобы клиент не мог обойти проверки и добавить пустую строку или дубликат.
Это инкапсуляция и сохранение инвариантов компонента.

**Почему событие, а не прямой вызов формы?**
Компонент должен быть переиспользуемым и не знать о конкретной форме.
Событие — это точка расширения и слабая связанность.

**Что будет, если подписчиков нет?**
`?.Invoke` просто ничего не сделает, ошибки не будет.

**Почему `SelectedValue` при отсутствующей строке сбрасывает выбор?**
Контракт такой: `set` выбирает существующее значение, а добавление — задача
`AddValue`. Поведение описано в XML-документации и README.

**Почему используется `UserControl`, а не наследование от `ComboBox`?**
`UserControl` позволяет собрать составной компонент и скрыть внутренний
`ComboBox`, не наследуя его поведение и не раскрывая лишние свойства.

**Как компонент подключить к другому проекту?**
Через ссылку на проект или NuGet-пакет `SelectionControlLibrary.Kiryushin`.
Источник пакета описан в `lab1/NuGet.config`.

# Лабораторная работа №2 — полный разбор и защита

**Вариант 13, оценка «3».**
Тема: компонентно-ориентированное приложение «Учёт продуктов».

---

## 1. Что требовалось

Для оценки «3» компоненты создаются **в одном решении** с основным проектом и
проектом-контрактом. Загрузка компонентов — через рефлексию или MEF, правила
доступа — через авторизацию по логину или файл лицензии.

Для варианта 13 нужны три компонента:

1. **Простой справочник** — категории изделий, `DataGridView` с одной колонкой.
2. **Сложный справочник** — продукты:
   * название;
   * описание;
   * категория — визуальный компонент выбора;
   * количество — визуальный компонент ввода с возможностью `null`;
   * вывод в виде дерева: категория → количество → название → идентификатор.
3. **Отчёт** — продукты выбранной категории в `DataGridView`.

Дополнительно: меню «Справочники»/«Отчёты», `TabControl`, закрытие вкладки
двойным кликом, роли `admin`/`user`/остальные.

## 2. Архитектура

```text
ComponentOrientedPlatform (контракт IComponentContract)
        ▲
        │ реализуют
┌───────┴──────────────────────────────────────────────┐
│ ProductCatalog.Components.SimpleDirectory           │
│ ProductCatalog.Components.ProductDirectory          │
│ ProductCatalog.Components.ProductReport             │
└───────┬──────────────────────────────────────────────┘
        │ DLL загружаются через рефлексию из Components
        ▼
ComponentHost
        ├── ProductCatalog.Data (SQLite)
        ├── SelectionControlLibrary (визуальные компоненты лабы №1)
        └── appsettings.json
```

Основное приложение **не использует типы компонентов на этапе компиляции**.
Оно знает только контракт, а реализации загружает из папки `Components`.

> В ветке `lab5` в `ComponentHost` также появились `PluginLoader` и
> `ExtensionsForm` — это лабораторная №3. К лабораторной №2 они не относятся.
> Аналогично `PluginDirectory` в `appsettings.json` — добавка лабы №3.

## 4. Контракт

```csharp
public interface IComponentContract
{
    string Id { get; }
    string Title { get; }
    ComponentSection Section { get; }
    AccessLevel MinimumAccessLevel { get; }
    UserControl CreateControl();
}
```

* `Section` — «Справочники» или «Отчёты»;
* `MinimumAccessLevel` — минимальная роль;
* `CreateControl()` — создаёт новый `UserControl` для вкладки.

Каждый компонент реализует контракт и возвращает свой `UserControl`.

## 5. База данных

SQLite-файл `productcatalog.db` создаётся рядом с исполняемым файлом.

```sql
CREATE TABLE Categories (
    Id   INTEGER PRIMARY KEY AUTOINCREMENT,
    Name TEXT NOT NULL UNIQUE
);

CREATE TABLE Products (
    Id          INTEGER PRIMARY KEY AUTOINCREMENT,
    Name        TEXT NOT NULL,
    Description TEXT NOT NULL DEFAULT '',
    Category    TEXT NOT NULL,
    Quantity    INTEGER NULL
);
```

Категория в продукте хранится **как текст**, без внешнего ключа — это требование
задания. При первом создании БД добавляются 4 стартовые категории.

## 6. Компоненты

### 6.1. Простой справочник категорий

* `DataGridView` с одной колонкой «Категория», `Dock = Fill`;
* `Insert` — добавляет строку и запускает редактирование;
* сохранение — по `Enter` или при уходе из ячейки (`CellEndEdit`);
* пустое значение запрещено (`CellValidating`);
* `Delete` — удаление выбранных строк с подтверждением;
* `F5` — перечитать данные.

Используется `CategoryRepository`.

### 6.2. Сложный справочник продуктов

* Основной элемент — `TreeViewPresenter` (визуальный компонент лабы №1/№2);
* иерархия: `Category` → `Quantity` → `Name` → `Id`;
* контекстное меню «Добавить/Редактировать/Удалить/Обновить»;
* горячие клавиши `Ctrl+A`, `Ctrl+U`, `Ctrl+D`, `F5`;
* удаление с подтверждением;
* форма `ProductEditForm`:
  * название и описание — `TextBox`;
  * категория — `ComboBoxSelector` из справочника категорий;
  * количество — `NullableIntInput` с флажком «Нет значения»;
  * ID в форму не выводится;
  * при редактировании поля заполняются;
  * при закрытии с изменениями — предупреждение.

### 6.3. Отчёт

* Стандартный `ComboBox` для выбора категории;
* кнопка «Сформировать»;
* `DataGridView` с колонками: идентификатор, название, описание, категория,
  количество;
* доступен только роли `Advanced` (`admin`).

## 7. Роли и загрузка компонентов

`LoginForm`:

| Логин | Роль | Компоненты |
|---|---|---|
| `admin` | Advanced | категории, продукты, отчёт |
| `user` | Basic | категории, продукты |
| любой другой непустой | Minimal | только категории |

`ComponentLoader`:

1. читает `ComponentDirectory` из `appsettings.json`;
2. перебирает `*.dll` из папки `Components`;
3. `Assembly.LoadFrom`;
4. `GetTypes`;
5. отбирает типы, реализующие `IComponentContract`;
6. `Activator.CreateInstance`.

`MainForm.BuildMenu` фильтрует компоненты по
`MinimumAccessLevel <= роль` и добавляет пункты в меню.

---

## 8. Как проходит работа

1. Пользователь вводит логин.
2. `MainForm` загружает компоненты из `Components`.
3. Строится меню по роли.
4. Клик по пункту меню создаёт вкладку с `UserControl`.
5. Вкладка закрывается двойным кликом по её заголовку.
6. Компоненты работают с общей SQLite-БД.

## 10. Чек-лист демонстрации

1. Войти под `admin` — видны «Категории», «Продукты», «Отчёт».
2. Открыть категории, показать 4 стартовые записи.
3. Нажать `Insert`, добавить категорию, нажать `Enter`.
4. Выбрать строку, нажать `Delete`, показать подтверждение.
5. Открыть продукты, через `Ctrl+A` добавить продукт с категорией и количеством.
6. Показать дерево «категория → количество → название → ID».
7. Нажать `Ctrl+U`, показать заполненные поля и предупреждение при закрытии.
8. Нажать `Ctrl+D`, показать подтверждение удаления.
9. Открыть отчёт, выбрать категорию, нажать «Сформировать».
10. Войти под `user` — нет отчёта; под произвольным логином — только категории.
11. Показать `appsettings.json`, папку `Components`, `ComponentLoader`.

## 11. Вероятные вопросы и ответы

**Где здесь компонентный подход?**
Контракт вынесен отдельно, три реализации — отдельные проекты. Основное
приложение загружает их динамически и не зависит от их типов на этапе компиляции.

**Почему компоненты в одном решении?**
Это критерий оценки «3». Для «4»/«5» нужны отдельные решения и NuGet-контракт.

**Как основное приложение находит компоненты?**
Через рефлексию и папку `Components`, путь задан в `appsettings.json`.

**Как ограничивается доступ?**
`LoginForm` определяет роль по логину, `MainForm` фильтрует компоненты по
`MinimumAccessLevel`.

**Почему категория — текст, а не внешний ключ?**
Так требует задание: справочник не связан с сущностью, в продукт пишется
текстовое значение. Проверка существования категории выполняется на уровне
приложения.

**Почему отчёт только для admin?**
Отчёты относятся к продвинутому уровню доступа; это логика `MainForm`.

**Какой визуальный компонент вывода использован?**
`TreeViewPresenter` — дерево по иерархии свойств/полей объекта.

**Что будет, если DLL компонента сломана?**
`ComponentLoader` перехватывает ошибку, добавляет её в список, приложение
показывает предупреждение, остальные компоненты продолжают работать.

## 12. Ограничения и нюансы

* компоненты и контракт — в одном решении, как и требуется для «3»;
* визуальный компонент вывода `TreeViewPresenter` добавлен в библиотеку
  лабораторной №1 в рамках лабы №2 (в лабе №1 на «3» блок вывода не требовался);
* ссылки основного приложения на проекты компонентов имеют
  `ReferenceOutputAssembly=false` — только для порядка сборки;
* отчёты доступны только `admin`;
* база — SQLite; для лабы №5 она заменяется на PostgreSQL.

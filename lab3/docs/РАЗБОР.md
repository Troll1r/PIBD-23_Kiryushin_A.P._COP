# Лабораторная работа №3 — полный разбор и защита

**Вариант 13, оценка «3».**
Тема: плагины формирования документов.

---

## 1. Что требовалось

1. Реализовать от 1 до 3 контрактов плагинов.
2. Доработать проект лабы №2, чтобы он формировал данные для отчётов через плагины.
3. Использовать свои плагины и плагины одногруппников.

По критерию на «3»:

* создать плагин под простой документ (текст/картинки/простые таблицы);
* сформировать через плагины **первый документ варианта** и **документ с диаграммой**.

Для варианта 13:

* документ с большим текстом — Excel;
* документ с линейной диаграммой — Excel (в таблице варианта);
* документ с таблицей со сложной шапкой — Excel (для «4»/«5»).

В тексте задания для диаграммы указана **круговая диаграмма в PDF**, поэтому
реализованы **оба** варианта диаграммы: линейная Excel и круговая PDF.


Основное приложение не знает типы плагинов. Оно знает только контракты и
загружает реализации из папки `Plugins`.

## 4. Контракты

```csharp
public interface IReportDocumentContract
{
    string DocumentFormat { get; }
}

public interface IReportDocumentWithContextTextsContract : IReportDocumentContract
{
    Task CreateDocumentAsync(
        string filePath,
        string header,
        List<string> paragraphs);
}

public interface IReportDocumentWithChartLineContract : IReportDocumentContract
{
    Task CreateDocumentAsync(
        string filePath,
        string header,
        string chartTitle,
        Dictionary<string, List<(int Parameter, double Value)>> series);
}

public interface IReportDocumentWithChartPieContract : IReportDocumentContract
{
    Task CreateDocumentAsync(
        string filePath,
        string header,
        string chartTitle,
        string seriesName,
        List<(string Parameter, double Value)> series);
}
```

`DocumentFormat` — строка `"xlsx"`, `"pdf"` или `"docx"`. По ней форма
заполняет выпадающие списки.

## 5. Плагины

### 5.1. Текстовый Excel

`TextExcelReportPlugin`:

* `DocumentFormat = "xlsx"`;
* принимает заголовок и список абзацев;
* создаёт Excel-книгу через ClosedXML;
* каждый абзац — отдельная строка с переносом текста.

Основное приложение передаёт по абзацу на каждый продукт в наличии:
название и описание.

### 5.2. Линейная диаграмма Excel

`LineChartExcelReportPlugin`:

* `DocumentFormat = "xlsx"`;
* принимает словарь серий;
* для варианта 13 каждая серия — категория, единственное значение — количество
  отсутствующих продуктов;
* создаёт таблицу «Категория — Количество» и вставляет изображение линейной
  диаграммы.

### 5.3. Круговая диаграмма PDF

`PieChartPdfReportPlugin`:

* `DocumentFormat = "pdf"`;
* принимает список «категория — количество»;
* строит круговую диаграмму и PDF через QuestPDF;
* добавляет заголовок, диаграмму и таблицу значений.

## 6. Загрузка плагинов

`PluginLoader`:

1. читает `PluginDirectory` из `appsettings.json`;
2. ищет `ProductCatalog.Plugins.*.dll`;
3. `Assembly.LoadFrom`;
4. `GetTypes`;
5. отбирает типы, реализующие нужные контракты;
6. создаёт экземпляры через `Activator.CreateInstance`;
7. читает `DocumentFormat`.

`AssemblyResolve` ищет зависимости в папке плагинов и в папке приложения.

DLL плагинов и их зависимости при сборке автоматически копируются в
`ComponentHost/bin/<Configuration>/net9.0-windows/Plugins` и в каталог
приложения.

---

## 7. Форма «Расширения»

Три блока:

1. «Документ с текстом (Excel)»;
2. «Документ с линейной диаграммой (Excel)»;
3. «Документ с круговой диаграммой (PDF)».

В каждом блоке:

* `ComboBox` с доступными форматами, полученными из плагинов;
* кнопка «Создать документ...»;
* `SaveFileDialog`;
* вызов `CreateDocumentAsync`;
* сообщение об успехе/ошибке.

Пункт меню: **«Отчёты → Расширения»** (доступен администратору, как и отчёты
в лабе №2).

---

## 8. Как формируются данные

`ExtensionsForm` берёт `ProductRepository.GetAll()`:

* для текста — продукты с `Quantity > 0`;
* для диаграмм — продукты с `Quantity is null or <= 0`, сгруппированные по
  категориям.

Текстовый отчёт: «Название + Описание» по каждому продукту в наличии.
Диаграммы: количество отсутствующих продуктов по категориям.

## 11. Вероятные вопросы и ответы

**Почему три плагина, если разрешено от 1 до 3?**
На «3» нужны первый документ и документ с диаграммой. В задании противоречие:
таблица требует линейную диаграмму Excel, текст — круговую PDF. Сделаны оба
варианта, поэтому плагинов три. Это в пределах разрешённого максимума.

**Почему не один плагин?**
Одного своего текстового плагина достаточно только при наличии чужого плагина
для диаграммы. Чужих плагинов нет, поэтому диаграмма реализована своя.

**Как приложение находит плагины?**
Через рефлексию: `Assembly.LoadFrom`, `GetTypes`, поиск реализаций контрактов,
`Activator.CreateInstance`.

**Как определяется формат?**
Свойство `DocumentFormat`; по нему заполняются `ComboBox`.

**Почему приложение не падает без плагинов?**
`PluginLoader` обрабатывает ошибки, форма показывает пустые списки и
отключённые кнопки; основной функционал лабы №2 продолжает работать.

**Почему в Excel линейная диаграмма — изображение?**
Документ содержит таблицу данных и график; для учебной работы это допустимо.
Если требуется нативный объект диаграммы Excel, нужно использовать EPPlus или
аналогичную библиотеку.

**Где третий плагин таблицы со сложной шапкой?**
Для «3» он не требуется; это контракт для «4»/«5». В работе реализованы
текст + две диаграммы.

**Почему отчёты доступны только admin?**
Это следствие правил доступа лабы №2: меню «Отчёты» относится к Advanced.

## 12. Ограничения и нюансы

* для линейной диаграммы Excel используется изображение, а не нативный график;
* третий контракт варианта (таблица со сложной шапкой) не реализован — для «3»
  не нужен;
* используются только свои плагины; архитектура готова принять чужие DLL в
  папку `Plugins`;
* плагины зависят от ClosedXML, QuestPDF и System.Drawing; зависимости
  копируются автоматически;
* PDF-файлы заданий в репозиторий не включены.
